# 重大角色決策：從規劃交到正文

用於會改變弧線、造成不可逆損失或讓人物承擔重大風險的選擇。日常動作、過渡場景不需要另填表或增加審稿輪次。角色可以衝動、自欺、誤判或拒絕行動；讀者需要理解這個人物在此刻為何如此選擇。

## 規劃時建立什麼

沿著角色的處境寫清楚：他想保住什麼、決策前知道或相信什麼、還能採取什麼行動、新資訊或壓力如何使某個選項勝出。把「他知道有風險」和「他仍選擇它的理由」分開；有備案也不能自動證明風險值得承擔。

替代行動須符合故事條件，例如等待、求援、先查另一項線索、繼續原方案或拒絕配合。按場景需要選取，勿為湊數安排明顯荒唐的選項。思考不行動的代價，以及風險落在本人或他人身上時，角色為何接受這種分配。

理由可以來自價值優先、情感、專業判斷、過往經驗或錯誤信念，不需要成功保證或最優答案。若角色低估了後果，保留能讓讀者辨認其盲點的動作或資訊；不要在事後用成功替原決定辯護。

## 可選的章計畫交接

YAML beat 可在重大選擇使用 `decision_points`。只有 `character`、`choice` 是存在條目時的必填非空文字；其他欄位依該決策所需使用。舊計畫可繼續在 `key_events` 表達，不自動補標。

| 欄位 | 用途 |
|---|---|
| `character` | 作決定的人；不一定是本章 POV |
| `choice` | 具體選擇的行動或拒絕 |
| `trigger` | 決策前的資訊、刺激或期限；為何在此刻發生 |
| `options` | 文字列表：可信替代行動及相關代價 |
| `reasoning` | 按其所知／相信、欲望／情緒說明取捨 |
| `accepted_cost` | 角色已預見且願意承擔的代價，包括影響別人的風險 |
| `uncertainty` | 未確認事項、誤判或未察覺的盲點；保持角色知情邊界 |

文字欄位使用字串，`options` 使用字串列表。不加入未約定欄位；拼字或型別錯誤會報錯，缺少可選內容則交給作者按情節判讀。這是交接格式，不是對動機完整性的程式評分。

整項放入章前包的必要 `author_intent`，引用本章 beat 行段；不得壓成只剩結論、因預算略去代價，或轉成 `knowledge`／已發生紀錄。角色在本章中才取得的資訊，要先在場景中取得再作決定；作者預定後果不是角色此刻知道的事。其他角色的動機仍依 POV 呈現可觀察言行，不直接寫入視角人物的內心。

既有單次記憶查詢也可使用決策中的人物、行動、觸發、理由與未知事項作查證線索。兩後端共用查詢組裝，總長維持1,200字元，決策線索優先使用至多600字元；過長單項完整略過，其餘空間留給原 beat。這只影響找資料的入口，不增加呼叫，也不把查詢文字認定為記憶證據。缺欄／空列表仍使用原查詢；線索受篇幅省略時，作者可按具體缺口補查。

## 作者如何使用

正文用對話、猶豫、拒絕、先做哪件事、內心判斷等適合該章的方式，讓選擇有可辨認的依據。不要把上述欄位逐項念成決策報告。計畫已寫出理由，不代表讀者已在正文看見理由。

動手前核對重要依據的時間與來源。缺漏時先分辨：規劃沒建立、原文已有但記錄漏掉、上下文省略、召回漏查，或正文表達不足。沿現有來源補查或在授權範圍內補足規劃；需要改世界規則、重大情節或既有人物設定的方案交回主代理處理，勿自行加一個安全保證。

## 輕量審稿怎麼挑戰

對重大選擇找出正文位置，回答三個連在一起的問題：什麼使人物作這個決定？為何此刻採這個行動、放棄可行的其他路？他預見、低估或拒絕面對哪些後果？理由可分散在前文，不要求每次重述或長篇內心獨白。

若證據只顯示人物知道風險、簽名承擔或作者安排了轉折，指出取捨在哪裡沒有成立。反過來，若欲望、情緒或錯誤信念已支持行為，就不要因結果糟糕而一律判成動機缺失。未解的動機問題帶回規劃／寫作處理；`complete: true` 仍只表示產物一致，沒有文學品質證明。

交接的來源／預算測試驗證資訊能到達作者；場景演練另驗證作者／編輯是否會追問選擇的根據。不要把機械通過當成動機已成立或小說品質已普遍改善。
